# JS/Wasm and SIMD experiments

Production uses one Wasm decode/verify call, with portable SIMD128 BLAKE3 and
native browser gzip/base64. These harnesses compare alternatives; they are not
runtime dependencies. NeoX's code is 0BSD. The existing frozen references retain
their notices.

The selected kernel hashes four complete, non-final 1,024-byte chunks in parallel.
It preserves chunk counters, merge order, scalar tails, root flags, exact bytes,
buffer ownership, options and errors. SIMD rounds keep a loop to save compressed
code; scalar parent/tail rounds use fixed schedules. The public API is unchanged.

## Reproduce the selected comparison

From the repository root, with the documented Rust/Node tools and Wasm target:

```sh
cargo run --release --locked --example hybrid_prototype -- --prepare
cargo run --release --locked -- build --all
cargo run --release --locked -- bench prepare
CHROMIUM_BIN=/usr/bin/chromium CHROMIUM_VERSION=156.0.8078.79 COMPARE_DATASETS=all \
  node benchmarks/compare.cjs generated/performance/baseline.mjs \
  dist/full.min.mjs generated/performance/paired.json
```

Preparation reads the v0.2.0 tag, so fetch that tag in a shallow checkout. Inputs are deterministic public fixtures. Set `COMPARE_DATASETS` to a comma-separated
selection to narrow a run; omitted means the five public pattern/size cases.
The GitHub benchmark workflow's `paired` choice measures public fixtures on x64.

The harness compares actual output bytes and buffer shape before timing, then
measures the entire synchronous call. Both implementations receive the same
packet and options, alternate order and use a shared calibrated batch. It records
all measured observations, actual batch sizes, browser, architecture and module
SHA-256 hashes. Do not combine timings from separate experiments into a synthetic
complete-call estimate. Loading, cold initialization and peak memory are not
measured by this harness.

## Component and rejected candidates

```sh
# Four standalone hash kernels, generated entirely under ignored scratch space.
cargo run --release --locked --example hybrid_prototype -- --prepare
CHROMIUM_BIN=/usr/bin/chromium CHROMIUM_VERSION=156.0.8078.79 \
  node benchmarks/experiments/hybrid/measure.cjs

# JS reference unpacker with a Wasm hash; deliberately experimental.
cargo run --release --locked --example hybrid_prototype -- \
  generated/performance/hashes-simd-loop.wasm generated/performance/hybrid.mjs

# Assemble a matching decoder kernel through the production ESM adapter.
cargo run --release --locked --example adapter_prototype -- \
  generated/performance/candidate.wasm generated/performance/candidate.mjs
```

`measure.cjs` distinguishes resident hashing from input-copy-plus-hashing and
compares bytes with known fixture digests. It uses three browser processes and
nine measured batches after warm-up. Its component results do not predict the
cost of a different unpacker, bridge or module layout.

The following patches are against the sources used during the experiment and
are for manual inspection/reproduction, not an automatic supported build mode:

| Candidate | Observation in the tested complete calls |
| --- | --- |
| JS reference + SIMD hash (`hybrid_prototype.rs`, `hash-loader.js`) | Faster on one 1 MiB case, slower on larger inputs; rejected. |
| Native string builtins (`string-input.patch`, `string-shim.wat`) | Higher bridge/runtime cost and larger module; rejected. Requires a modern engine or the experiment's fallback. |
| Eight-character copy loop (`copy-unroll8.patch`) | No reliable gain; rejected. |
| Paired 32-bit input stores (`copy-words.patch`) | Small, inconsistent gains, extra code; rejected. |
| Looped scalar tails/parents (`compact-tail.patch`) | Smaller compressed code, materially slower secure calls; rejected. |
| Fully unrolled SIMD rounds (generated by `--prepare`) | Similar component speed, larger gzip payload; selected looped SIMD instead. |

The selected production kernel requires only ordinary SIMD128, available before
Chrome 109; it uses no Wasm string builtins, GC, relaxed SIMD, threads or workers.
An explicit scalar build remains possible with
`RUSTFLAGS="-C target-feature=-simd128"`. `tests/file.cjs` checks both supported
ends of the browser range locally without fetch or file-access exceptions.
